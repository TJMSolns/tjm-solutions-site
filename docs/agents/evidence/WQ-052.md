# Evidence — WQ-052

**Item:** SPIKE — decide the coverage strategy for the accessibility gate before WQ-051 implements it.
Output: a decided approach, recorded as POL-003 / DR-003.

Commit: f4b6054

Run-count: 4 measurements at decision time (2026-08-18), all against a served production build
(`npx docusaurus serve --port 3002`, 8-core machine, `nproc`=8).
(1) Page inventory parsed from `build/sitemap.xml`: **74** URLs — 34 articles, 22 offer pages,
11 mdslides, 5 top-level, 2 articles index/tag. This corrects WQ-051's stated "~51 pages", which
omitted the mdslides section.
(2) Serial baseline: 6 pages sequentially in **12.895s** (~2.15s/page).
(3) Parallel baseline: same 6 pages at `xargs -P 6` in **6.159s**. Small samples are dominated by
Node startup, so this was not used as the rate.
(4) Full sweep, the decisive measurement: all **74 pages** at `xargs -P 6`, light theme, in
**60.303s** (~1.03s/page wall-clock, `user 2m13s` confirming real parallelism). Both themes is 148
runs, extrapolating to ~2 minutes — linear in run count, since each pa11y invocation is an
independent process.

Invariance-recheck: The decision does not rest on the extrapolation alone. The load-bearing claim is
that the full sweep is affordable, and that was measured directly at 74 pages rather than inferred
from the 6-page sample — which matters, because the 6-page sample would have implied ~2.15s/page
serial and overstated the cost by roughly 2x. The dual-theme figure is the one extrapolated value,
and it is a doubling of run count against a per-run cost measured across 74 real invocations, not a
projection from a micro-benchmark.

The decision was also stress-tested against the alternative it displaces. Option (a)'s unsoundness
was not taken on faith from the WQ-052 row: the mechanism is that page accessibility depends on
shared CSS, components, tokens and Docusaurus version, and this session produced a concrete instance
— the WQ-056 contrast failure is a single shared syntax-highlighting token (`rgb(98, 114, 164)` at
3.03:1) manifesting on 3 unrelated pages, none of which would be re-checked by a source-change-keyed
cache. That is the same failure class as WQ-042's gray-scale token bug, now observed twice.

Strongest evidence that full coverage is the right call, and independent of any timing argument: the
measuring run was itself the first full sweep ever performed on this site, and it immediately found a
live WCAG2AA violation on production (WQ-056) that the incumbent 4-URL gate structurally could not
find, since none of those four pages contains a code comment. A 10% random sample would have found it
only on a lucky draw, and non-reproducibly.

Residual risk, stated plainly: the policy is measurement-dependent and the site will grow. That is why
POL-003 carries an explicit revisit trigger at 5 minutes wall-clock (~145 pages at the measured rate)
and names option (c) as the successor design, rather than leaving a future session to quietly narrow
the gate.
