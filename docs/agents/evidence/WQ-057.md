# Evidence — WQ-057

**Item:** No dependency-vulnerability signal exists; raw `npm audit` numbers (57 total, 3 critical) are
misleading for a static site since every dependency is build-time and the 2026-08-18 measurement found
zero evidence any flagged package's code reaches the shipped `build/` output.

**Design decision:** don't try to classify all 57 flagged packages generically as build-time-vs-shipped.
A first attempt matched bare package names anywhere in `build/` and produced heavy false-positive noise:
ordinary English words ("express", "ws", "uuid") matching in article prose, and coincidental substring
matches unrelated to the package ("qs" matching Prism's Q# language alias, literally `alias:"qs"` in
the syntax-highlighting bundle). A second attempt restricted to JS files with module-reference-shaped
matching still couldn't reliably separate "flagged package's code legitimately ships because it's part
of the framework" (e.g. `@docusaurus/theme-classic`, `dompurify`) from "flagged package has no business
being in a static site's output" (e.g. `puppeteer`), because framework packages are *supposed* to
appear in the bundle and their mere presence isn't a finding.

**Final approach (`scripts/check-shipped-vulns.js`):** a curated denylist of packages with zero
legitimate reason to ever ship in a Docusaurus static build (`webpack-dev-server`, `puppeteer`,
`puppeteer-core`, `@puppeteer/browsers`, `pa11y`, `basic-ftp`, `extract-zip`, `shell-quote`, `sockjs`,
`websocket-driver`, `express`, `http-proxy-middleware`, `launch-editor`, the exact set the original
2026-08-18 investigation named). The script always prints the raw `npm audit` summary as informational
context, then checks only the denylist intersection against `build/**/*.js` with module-reference-shaped
matching, and gates (exits 1) only on a real match there. Verified the fail path works, not just the
pass path: a synthetic build directory with `require("node_modules/pa11y/index.js")` correctly fails
with exit 1; the real `build/` directory correctly exits 0, clean.

**Documented decision on what gates, per the item's own ask:** the shipped-code check is the gate
(wired into CI as a new `vuln-check` job, `needs: build`, and `deploy` now `needs: [build, vuln-check]`
so a real finding blocks publishing). Raw `npm audit` counts are never a gate on their own, printed for
visibility only. `npm audit fix --force` remains explicitly not run (the item already found it would
downgrade `pa11y` three majors back).

**Also fixed in the same pass:** `package.json`'s `wcag:check` script still hardcoded `/about`, retired
earlier this session; swapped for `/tony`.
