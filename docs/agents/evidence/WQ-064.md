**The "no offline caching" decision, and a real schema constraint found while implementing:**
`offlineModeActivationStrategies: []` (the literal "never" value) is rejected by the plugin's Joi
schema (`"offlineModeActivationStrategies" does not contain 1 required value(s)`; Joi's
`.items(x.required())` means at least one item must be present, not "if present, must match x"). Used
`['queryString']` instead, the least-intrusive of the 6 allowed strategies: offline mode only ever
activates if a specific query string is present in the URL, never automatically for a normal visitor or
on install. Read `node_modules/@docusaurus/plugin-pwa/lib/sw.js` to confirm what this actually means at
runtime: the service worker installs and activates unconditionally (satisfying installability
criteria), but its `fetch` listener and cache-population logic are both gated on a `params.offlineMode`
flag that only turns on via one of the configured activation strategies. With only `queryString`
configured, that flag stays off for every normal visit, so the SW's fetch handler never intercepts a
request or caches anything, it's a real, installed, but inert service worker.
