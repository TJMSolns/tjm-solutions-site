# WQ-073 evidence: CI link check fixed for scholarly reference lists

- **Trigger:** the 2026-10-15 thesis article added a reference list. From then on the `Link check` job failed on
  every run: 64 errors in run 39057515341, none of them a 404.
  - 50 were DOIs answering 403. The publishers (ACM, Wiley, Emerald, Biometrika, World Scientific) block bots
    behind doi.org.
  - 10 were 202 Accepted: IEEE DOIs and EUR-Lex ELI links.
  - iso.org and ofcom.org.uk returned 403.
  - mckinsey.com failed with an HTTP/2 protocol error.
- **Approval:** Tony approved the housekeeping list that includes this fix (PDR-013 item 6, org DR-043, 2026-10-17).
- **Fix** (`.github/workflows/ci.yml`, new `scripts/check-dois.sh`):
  - **DOIs** are excluded from lychee. They are checked instead against the DOI registry (doi.org handle API),
    which answers 200 for a registered DOI and 404 for one that doesn't exist. Broken DOIs are still caught.
  - **202 Accepted** is accepted. It is not an error.
  - **iso.org, ofcom.org.uk and mckinsey.com** are excluded, with the reason in a CI comment. This follows the
    existing medium/linkedin precedent; the three links were verified by hand when the article was drafted.
- **Verified locally:**
  - `scripts/check-dois.sh build`: 77 DOIs checked, 0 not found.
  - Negative test with a fake DOI (`10.1145/9999999.0000001`): the check reports it and exits 1.
  - lychee (docker `lycheeverse/lychee`) with the new arguments over `build/`: 5458 links, 0 errors.
- **CI:** run 39058009909 (commit `688cdfe`): Build, Shipped dependency check, Deploy and Link check all pass, including the new DOI registry step.
