# WQ-077 evidence: validation docs match the released behaviour (MD-Slides v1.1.2)

- **Defect (found by the WQ-075 verifier, 2026-10-21):** `mdslides-docs/validation.md` promised every problem in one
  pass; the v1.1.1 jar stopped at the first structural error, hid density warnings behind errors, reported a missing
  image only after "Validation passed", and left an empty output folder on a failed render.
- **Resolution:** the code was changed to match the docs. MD-Slides v1.1.2 (`DeckCheck`, MD-Slides MS-033) checks
  every slide before anything is written; CLI validation, render and the MCP `validate_deck` share it.
- **Site:** `validation.md` shows real multi-slide v1.1.2 output; the live demo was rebuilt from the v1.1.2 release
  (`scripts/build-mdslides-demo.sh v1.1.2`) and deployed in `ed29224`.
- **Browser check:** `node scripts/verify-mdslides-demo.mjs https://www.tjm.solutions/mdslides/demo <downloaded jar>`
  after the deploy: 23/23 (navigation, speaker sync, goto, history, break, tokens, phone and laptop fit, session log
  and `report`, 51-page PDF, WCAG 2.1 AA on all 52 pages).
- **CI on `ed29224`:** build, shipped-dependency check and deploy succeeded; the link check failed only on the two GS1
  links (WQ-076).

## After the VETO (2026-10-24)
- **Length limits:** the docs were wrong. Character limits (heading and author 80, caption 100) are errors in the code
  by design; `validation.md` now lists them under Errors, and the density table lists only line and word guidance.
- **Two-column columns:** the code was wrong (the columns had no constraints, though the docs, `writing-slides.md` and
  the feature tour all promise the limits). MD-Slides v1.1.3 (MD-Slides MS-034, commit `0164759`) adds them as
  warnings; tour slide 38 trimmed to fit. The docs also say a two-column `##` heading belongs to the left column.
