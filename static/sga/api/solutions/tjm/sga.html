type ElitistReplacement[G] = (Vector[Scored[G]], Vector[Scored[G]]) => Vector[Scored[G]]

A standard "merge current + offspring, keep the top S by fitness" elitist replacement.

A standard "merge current + offspring, keep the top S by fitness" elitist replacement.

A genuinely different shape from Replacement[G], not a variant of it: deciding who survives needs fitness of both populations, so both are Vector[Scored[G]] in and out, never bare Vector[G].

This is a standard technique, not a replication of a PCKaNN source: neither Moores 1998 nor Moores 2000 describes this specific merge-and-truncate mechanism. The thesis does describe its own (later, LGA-specific) insertion method as "elitist" in passing — "any chromosome in the population must be somewhat fit as time elapses" — but only qualitatively, never confirming this exact merge-and-truncate mechanic. This implementation is a legitimate, standard elitist-replacement technique, not a verified replication of anything Moores specifically described.

def breed[G](scored: Vector[Scored[G]], offspringCount: Int, select: () => G, crossover: () => G, mutate: () => G): () => Vector[G]

Produces offspringCount new genomes from a scored population by repeating Mitchell's reproductive step: select two parents, cross them, mutate both children, repeat. This function knows nothing about what a genome is or what select/crossover/mutate do — it only knows how those pieces relate.

Produces offspringCount new genomes from a scored population by repeating Mitchell's reproductive step: select two parents, cross them, mutate both children, repeat. This function knows nothing about what a genome is or what select/crossover/mutate do — it only knows how those pieces relate.

Known limitation, deliberately deferred: this recurses through nested Rand closures, one level per offspring pair, so it isn't stack-safe for very large populations.

def bruteForceSelect(fitness: () => Vector[Boolean], numFeatures: Int): Scored[Vector[Boolean]]

Exhaustively enumerates every one of the 2^numFeatures possible feature-selection masks and returns the single best-scoring one, against the existing, unmodified Fitness[Vector[Boolean]] type -- no new architecture (Aghazadeh, "Applied Reinforcement Learning" Ch4, "the curse of dimensionality"). A real correctness-validation tool sga didn't have before: every small-search-space demo (Iris's 2^4=16) could only ever trust the GA found the true optimum because runs happen to converge to the same answer; this proves it against exhaustive ground truth. Only tractable for small numFeatures by design -- gas-sensor's 2^128 is exactly the regime a GA earns its keep over this, not a case this function is meant to handle.

A real correctness-validation tool sga didn't have before: every small-search-space demo (Iris's 2^4=16) could only ever trust the GA found the true optimum because runs happen to converge to the same answer; this proves it against exhaustive ground truth. Only tractable for small numFeatures by design -- gas-sensor's 2^128 is exactly the regime a GA earns its keep over this, not a case this function is meant to handle.

Signature deliberately has no label type parameter (no bruteForceSelect[L](...)): Fitness[Vector[Boolean]]/Scored[Vector[Boolean]] are already closed over any label type L a caller's dataset uses (that's Classification.fitness's own job), so no L actually appears anywhere in this function's real type.

Ties are real, not just theoretical: against real Iris data, two masks ({sepal_length, petal_width} and {petal_length, petal_width}) tie at the true global optimum (BruteForceSelectDemoSuite). maxBy keeps the first max encountered, not an arbitrary one -- so the returned mask on a tie is deterministic, whichever mask sorts first by this function's own enumeration order (increasing binary value of the mask, bit 0 = feature 0), not by dataset-specific meaning.

def pcknnStep[G](state: RunState[G], fitness: () => G, cull: () => G, select: () => G, crossover: () => G, mutate: () => G, replace: () => G): () => RunState[G]

PCKaNN's reproduction stage, genuinely different shape from Mitchell's step: cull runs before selection (a whole-population operation), and replace is elitist (needs fitness of both populations). Still takes select as its own parameter, same as Mitchell's step — the engine doesn't hardcode Selector.uniform even though it's the textbook-correct pairing method after truncation culling (Mühlenbein: cull to the top fraction, then mate uniformly among survivors); that choice belongs to whoever assembles PcknnAlgorithm, not to this function.
