object Csv

One Stage-1 decoder among several possible ones: turns CSV lines into the source-agnostic RawRow shape. An API-fetch or data-lake decoder would live alongside this, same signature shape, and neither RawRow.toDataset nor anything downstream would know the difference.

One Stage-1 decoder among several possible ones: turns CSV lines into the source-agnostic RawRow shape. An API-fetch or data-lake decoder would live alongside this, same signature shape, and neither RawRow.toDataset nor anything downstream would know the difference.

Deliberately minimal: no quoted-field escaping. Fine for the plain numeric CSVs this project targets so far; a dragon to revisit if a source ever needs a field containing a literal delimiter character.

headers/delimiter generalized from a hardcoded header-row/comma assumption, motivated by real data, not speculatively: 4 of the 6 chemical datasets considered for this project violated one or both (Wine/ Glass have no header row; QSAR/Wine Quality are semicolon-delimited). Defaults preserve the original behavior exactly, so every existing caller is unaffected.

object Libsvm

Another Stage-1 decoder, same seam as Csv — proves the pluggable- source design against a genuinely different real-world format, not just a second copy of CSV parsing. libsvm-sparse: one measurement per line, <class> <index>:<value> <index>:<value> ....

Another Stage-1 decoder, same seam as Csv — proves the pluggable- source design against a genuinely different real-world format, not just a second copy of CSV parsing. libsvm-sparse: one measurement per line, <class> <index>:<value> <index>:<value> ....

Deliberately minimal, same posture as Csv's "no quoted fields": assumes every measurement declares all featureCount indices (verified true of the gas-sensor fixture this was built for — every line has exactly featureCount feature:value pairs, indices 1..N with no gaps) rather than handling genuine libsvm sparsity (a dataset that omits zero-valued features, with missing indices defaulting to 0.0). A real dragon to revisit if a source ever needs that.

object Postgres

A Postgres decoder, same self-contained-source shape as Csv.parse/ Libsvm.parse (Either[String, Vector[RawRow]]), for the same reason: query is a caller-supplied SELECT producing both feature and label columns in one result set, so this never needs to know table/schema structure at all (design rationale: io-spikes.md).

A Postgres decoder, same self-contained-source shape as Csv.parse/ Libsvm.parse (Either[String, Vector[RawRow]]), for the same reason: query is a caller-supplied SELECT producing both feature and label columns in one result set, so this never needs to know table/schema structure at all (design rationale: io-spikes.md).

jdbcUrl carries NO embedded credentials -- a password inline in a URL is a well-known anti-pattern (shell history, any ps aux while the process runs), real even for a build-now feature, not a later-hardening concern. Credentials layer in from libpq's own standard convention instead: PGUSER/PGPASSWORD environment variables, the exact ones psql itself reads, not a new convention invented here.

Connection/statement/result-set lifecycle stays entirely inside this function (Using.Manager, closed even on failure) -- RawRow never gains a connection-shaped field to accommodate this, per io-spikes.md's own cross-cutting guardrail finding.

final case class RruffSpectrum(metadata: Map[String, String], points: Vector[(Double, Double)])

One RRUFF Raman spectrum: ##KEY=value metadata (mineral name, RRUFF ID, chemistry, locality, ...) followed by a raw (wavenumber, intensity) curve — a continuous spectral curve, not a fixed-length feature vector like every other real source sga reads today. RawRow.toDataset can't consume this directly; a spectrum needs resampling onto a fixed grid first (SpectralResampling) before it fits sga's one-row-per-sample shape.

type RawRow = Map[String, String]

A source-agnostic tabular row: column name to string value. The shared boundary type between however raw data arrives (CSV, an API response, a data-lake read, a stream) and the one, fully reused coercion into a typed Dataset. Adding a new source means writing a new Vector[String] => Either[String, Vector[RawRow]]-shaped decoder — toDataset below never changes.
