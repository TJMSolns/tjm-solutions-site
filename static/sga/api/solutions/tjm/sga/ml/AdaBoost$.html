AdaBoost

solutions.tjm.sga.ml.AdaBoost
object AdaBoost

AdaBoost over a fixed pool of Stump weak learners. Binary labels only (Dataset[Boolean]) -- deliberately, not Dataset[L] generically: the weighted-voting math needs a numeric +-1 sense, and making that a type constraint keeps the limitation visible at the call site rather than a hidden runtime assumption. Multi-class support (SAMME or one-vs-rest) is real, not-yet-solved work, not built here.

def fitness(pool: Vector[Stump], rounds: Int, parsimonyWeight: Double)(trainingSet: Dataset[Boolean], testSet: Dataset[Boolean]): () => Vector[Boolean]

A Fitness[Vector[Boolean]] over genomes that select a subset of pool -- the "GA-selected weak-learner pool" idea this technique is named for: the GA's job is choosing WHICH stumps AdaBoost gets to train with, not training the stumps itself. Held-out testSet deliberately, not leave-one-out: AdaBoost trains directly on whatever it's given, so leave-one-out's "train on everything else" shape would let it fit each left-out sample's neighbors too closely, overstating fitness. parsimonyWeight rewards smaller selected pools (fewer stumps = less overfitting risk, plus a simpler final ensemble) -- an arbitrary constant, same open- question status as Classification.fitness's own deferred reduction-reward weighting; a caller's choice, not a "correct" value invented here.

def predict(ensemble: Vector[(Stump, Double)])(features: Vector[Double]): Boolean

Weighted-majority vote: each stump's +-1 sense (true/false), scaled by its own trained weight (alpha), summed and thresholded at zero. Higher alpha -- lower weighted training error -- means more say in the final answer.

def train(pool: Vector[Stump], rounds: Int)(training: Dataset[Boolean]): Vector[(Stump, Double)]

Trains a boosted ensemble using only pool (already whatever a caller -- the GA-selected-subset fitness closure below, or a direct caller -- chose to include). Classic discrete AdaBoost: each round, pick the pool member with the lowest weighted training error, compute its vote weight (alpha) from that error, then reweight samples so misclassified ones count for more next round. Stops early, before rounds is reached, the moment no pool member beats chance (weighted error >= 0.5) -- a real correctness necessity: alpha would be zero or negative past that point, contributing no information (or actively wrong information) to the vote, not a subtlety worth allowing.
