HierarchicalClustering

solutions.tjm.sga.ml.HierarchicalClustering
object HierarchicalClustering

Groups correlated features together -- a different question than either the GA's "which minimal subset maximizes accuracy" or Boruta's "is this feature distinguishable from noise": this asks "which features are redundant with each other." Reuses linalg's dot/norm directly: Pearson correlation is exactly the cosine similarity of two mean-centered vectors, nothing new needed.

def instanceClustering[L](instanceLabels: Vector[String], threshold: Double, distance: ClusterDistance, strategy: LinkageStrategy)(d: Dataset[L]): Vector[Vector[String]]

Agglomerative clustering over SAMPLES (rows), not features (columns) -- reuses agglomerate unmodified, just fed each sample's own feature vector instead of each feature's column (Brink, Richards & Fetherolf, "Real-World Machine Learning" Ch9). A more principled alternative to the ad hoc stratified subsampling sga has used repeatedly (gas-sensor, Wine Quality, Olive Oil) to fix leave-one-out's O(n²) cost -- picking one representative per cluster instead of a random per-class fraction is a real, not-yet-exploited follow-up use, not built here. instanceLabels names each row the same way featureNames labels cluster's output; must be parallel to d.samples (same positional-correspondence contract cluster already has with featureNames, not newly invented here). distance/strategy default the same way cluster's own do.

def pearson(a: Vector[Double], b: Vector[Double]): Double

A zero-variance (constant) vector centers to all-zero, giving a zero norm -- correlation with anything is undefined there, not NaN. Returns 0.0 (no signal to compare), the same total- function treatment Scaling.applyToFeatures already applies to exactly this shape of problem (a zero-variance feature there keeps its centered value instead of dividing by a zero std dev) -- pearson didn't apply it before, an FP audit finding: the NaN propagated silently into clusterSimilarity's sum and Mrmr's redundancy sum (Mrmr reuses this function directly), corrupting maxBy comparisons in both without any error signal.
